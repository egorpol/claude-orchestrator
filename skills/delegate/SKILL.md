---
name: delegate
description: Delegate coding, review, research or bulk-labelling work from Claude Code to Codex CLI or Cursor's headless agent (cursor-agent, model auto), weighing live quota (openusage) and Artificial Analysis ratings, running each delegate in its own git worktree with automatic checks, cross-vendor review and follow-up rounds, and reviewing its diff before merging. Use when the user asks to offload or parallelise work to Codex, Cursor or "another agent", asks how much Claude/Codex/Cursor quota is left, or asks which model to use for a task. Also use it unprompted before doing mechanical work inline that has a clear spec (tests from a written spec, the same update across several docs, a near-copy of an existing script), because Claude's own quota is the scarcest pool.

# Delegate

One CLI: `~/.claude/skills/delegate/scripts/delegate` (stdlib Python; full path, or `delegate` after `install.sh --bin` links it into `~/.local/bin`). Source of truth is `egorpol/claude-orchestrator`; `~/.claude/skills/delegate` symlinks into it. Commit edits there.

| command | does |
|---|---|
| `delegate quota [--source direct]` | % left, reset and pace for claude-5h/7d, codex-5h/7d, cursor-auto, cursor-premium; after PACE, median per-round pool cost and about-N-rounds-left when the logs have ≥3 clean samples |
| `delegate quota --unused [--since D] [--pool P]` | closed quota windows' peak use and unused share (from `quota.jsonl` only), plus median pool cost per (agent, model, effort, kind) from readings around delegate jobs |
| `delegate quota --snapshot --reason R [--if-active] [--job J]` | appends one direct reading of all pools to `~/.cache/claude-delegate/quota.jsonl`; runs by itself at session start and end, on each run start and job end, and from the `install.sh --timer` timer; `--job round-N\|review-N` tags the row |
| `delegate route <task> [--prefer IDs]` | ranks for `review`, `refactor`, `implement`, `research`, `bulk-label`; honours catalog `prefer` and `--prefer`; ROUNDS = rounds left in the tightest pool at the median per-round cost from the logs (n ≥ 3) |
| `delegate route --frontier [--json] [--refresh]` | runnable models (`cursor-agent models` without auto and the `-fast` ids, Codex's `~/.codex/models_cache.json` plus catalog models, Claude subagents), matched exactly to AA and placed on two frontiers, intelligence against `$/task` and against blended `$/1M`, each with its pool (`cursor-premium?` where the creator's pool is unverified); catalog delegates that are dominated or whose AA slug is gone; Cursor and Codex families with no rated row; the model `ask --agent both` falls back to when Codex is empty |
| `delegate ratings [--grep RE] [--refresh]` | AA intelligence / coding / tok/s / $ per 1M tokens (in, out, blended) and per AA index task (`$/TASK`) for catalog (or any AA) models |
| `delegate ask QUESTION [--files F]… [--agent cursor\|codex\|both]` | cheap read-only one-shot (default Cursor auto); cites `path:line` without filling orchestrator context. `both` asks Codex and Cursor in parallel for second opinions; when either reply has a `Pick:` line, a normalised `## picks` block follows. | `delegate cost --calibrate [--since D] [--json] [--quota-log P] [--save [--calibration P]]` | pool points per list-price USD and per token class, fitted on pairs of `quota --snapshot` readings against every Claude Code transcript (Codex pools: `~/.codex` rollouts), with bootstrap ranges, residuals, rises with no local calls, a timing check and correlated classes. On 2026-10-20: claude-5h 2.66 points per USD (a full window ≈ $38 at list price), claude-7d 0.36 (≈ $276); a full codex-5h window ≈ 16% of codex-7d. `--save` stores the fit with its date in `calibration.json` next to the quota log; `--by-mode` uses it until the next save, so re-save after a pool or price change |
| `delegate rate [--session ID] [--dry-run --print-packet]` | blinded item rater: Cursor Auto, in an empty temp dir and confined to it (`run_cursor(confine=True)`: any tool call outside it, any shell or subagent call ends the run, and the session is reported and skipped; `--agent codex` is refused, since Codex's reads show only as shell strings), reads only the session's typed prompts, its HANDOFF.md at session start and at session end (the SessionEnd copy, else the next session's start copy in the same repo if it began ≤30 min after the last call) and its commits, with mode words redacted, and splits the session into items (type, size, finished/partial/unclear, continuation). Each `/field-report` prompt starts its own `field-report` item, which `--by-mode` leaves out of the item counts. Appends a `rating` row (rubric `v2`, with `end_state`: `end`, `next-start` or null); by default rates drawn sessions quiet for 60 min that have no current rating |

Runs not yet applied or cleaned up that this session launched, or that had a round or review in its window, show as `live: not applied or cleaned up` in the skeleton only; `cleanup` writes their `runs.jsonl` row later; used by `/field-report` |
| `delegate report --auto [--backfill]` | one `summary` row per session in `~/.cache/claude-delegate/sessions.jsonl` (cost incl. subagents, mode, blocks, delegate commands, quota at start and end); `hooks/session-mode.py` runs it at session end, and with `--backfill` at session start for sessions that ended without SessionEnd. The last summary per session wins |
| `delegate report --select [--since D] [--until D] [--seed N] [--json]`, `delegate report --digest ID... --out DIR` | dry runs for automatic field reports, no agent calls. `--select` flags sessions without a hand report (a denied or blocked call, an idle cache rebuild, top-quartile cost units), takes the top 15 by rebuild share, then denials, then cost units, adds 5 random unflagged and 2 random flagged ones, keeps one session per mode, and prints why each was picked, with session prefixes only; `--seed` replays the draw. `--digest` writes `DIR/<prefix>/digest.md` (at most 60,000 characters: numbers, context trajectory, typed prompts, picker answers, HANDOFF.md at start and end, commits, harness notes, errors including ok-result failure lines, shell cwd moves/resets, ±3 rows around each friction event) and `transcript.txt` (the compressed main thread, with harness markers and error/cwd-reset suffixes), both cut before the first `/field-report` prompt. It drops a session whose kept rows hold a field-report Skill call or a write under `feedback/`, or that wrote HANDOFF.md after the cut, and exits 1 if it dropped any |
| `delegate launch codex\|cursor --brief F [--verify CMD] [--include-uncommitted [--all-untracked]] ...` | worktree on `delegate/<name>`, brief + contract, background run, log, last message, checks; Codex quota below `min_quota_pct` warns but launches (warning saved and repeated in the exit packet). `--include-uncommitted` snapshots the dirty main tree as the run's base (incompatible with `--base`; refuses >100 untracked files or 10 MiB unless `--all-untracked`); `changes.patch` then covers only the delegate's work |
| `delegate launch ... --verify CMD --preflight` | worktree and links, the check once at the base in the delegate's environment, its output tail and exit code, then removes it all; no agent starts. Warns when the check exits 0 but its full output has a failure line |
| `delegate review NAME [--agent ...] [--focus TEXT]` | read-only review of a run; by default the *other* vendor. Low Codex quota swaps a default Codex reviewer (no `--agent` or `--model`) to the `route --frontier` fallback model; if no fallback is available, keeps Codex with a warning. `--agent codex` or `--model` overrides the swap and warns when low |
| `delegate review --working-tree --brief F [--base REF] [--agent …]` | read-only review of uncommitted main-checkout work (tracked + non-ignored untracked); both vendors in parallel by default (Codex gpt-6.1-sol @xhigh + Cursor auto). Snapshot via a temp index (real index/HEAD untouched). Refuses over 100 untracked files or 10 MiB unless `--all-untracked`. `--link` takes gitignored paths only (live symlinks, not in the digest). Gitignored paths are absent from the snapshot. `--agent codex` warns at low Codex quota, as `launch` does. `cleanup NAME` afterwards; each call is a new run |
| `delegate followup NAME --brief F \| --from-review N [--fresh --model M] [--link PATH]` | next round in the same worktree, resuming the session; `--link` as on launch. A Codex run keeps Codex when quota is low, with a warning saved and repeated in the exit packet |
| `delegate verify NAME [--cmd C]` | re-run the check in the worktree, in the same scrubbed environment as the run's own verify step (stdin closed, no `__pycache__`); `--cmd` writes `verify-adhoc.log` and leaves the stored result alone |
| `delegate status [NAME] [--full]` | compact exit packet (default); `--full` for log tail and whole last message |
| `delegate wait NAME… [--timeout S]` | blocks until the run's round and reviews have finished and recorded, verify included; prints their packets. Exit 0 done, 1 failed, 3 timeout |
| `delegate diff NAME` / `apply NAME [--check]` / `cleanup NAME` | inspect, merge, tidy up. Each run is logged once to `runs.jsonl` in the runs root (what `cost` summarises): at `apply`, or at `cleanup` for read-only, hand-merged or discarded runs |

## Sessions

One work item per orchestrator session. An assessment or a plan counts as an item: hand off after it, before implementation starts. After an item is merged or committed, write a handoff (memory files plus a short `HANDOFF.md`: state, open PRs or runs, next step), then suggest a fresh session or `/clear`. At an item boundary above ~120k context, write the handoff and offer `/clear` in one line *before* starting the next item, even after "go on". A finished build that turns into Q&A support is a new item: its handoff covers tool URL, data layout and decided cases. Offer the `/clear` as an option in the picker that closes the first answer; as a closing sentence it was passed over four times while one session ran on to 223k (2026-10-11). Four sessions in a row (2026-10-10) ran 3–10 items each up to ~280k; clearing at those boundaries would have saved about 18–33% of each. Three sessions on 2026-10-11 started from a handoff and stopped at the next decision point: 18–21k cost units per call, against 24–29k for the sprawling ones and 67k for the 13-hour marathon. After `/clear`, `/next` (installed by `install.sh`) continues from `HANDOFF.md`. The context-guard hook (`hooks/context-guard.py`, via `./install.sh --hooks`) fires on the prompt from about 120k and again every 60k. `./install.sh --rules` puts these rules into every session, including ones that never load this skill. With `./install.sh --experiment` (opt-in control sessions), `hooks/session-mode.py` injects them instead, except in `vanilla` controls. `delegate cost --session latest` shows the current session's size and cost.

**Waits over an hour:** the prompt cache expires after 1h idle, so the turn that wakes up re-writes the whole context at 2×. Over 14 logged sessions, such rebuilds were 12.7% of all orchestrator cost: half after a user's break, half when a long run's notification woke the session. Before a multi-hour wait (a long run, a crawl), write the handoff and continue in a fresh session with `delegate wait`. The context guard holds the first typed prompt after 60 min idle at 100k+ context once and suggests `/clear`; it lets task notifications through. `delegate cost --session` lists the rebuilds.

## Workflow

**Delegate unprompted** by default when a part is mechanical and has a clear spec: every build step with a written spec, all test and doc writing, a near-copy of an existing script, or any step expected to write more than ~40 KB. Prefer a delegate pool whose pace is >1 (share left / share of window left); check `delegate quota` at dispatch, and send work to Cursor when Codex 5h is nearly full even if Codex 7d looks spare. From 2026-10-13 to 10-26 Codex 7d and Cursor Auto mostly reset unused while Claude 7d ran at 97–99% used on Pro; on Max (since 2026-10-26) Claude may no longer be the scarcest pool. Keep pure judgement, data checks and adjudicating reviews here. Not for changes under ~10 lines unless the user asks: a six-line CSS change took about 8 orchestrator calls through `delegate` (brief, launch, verify, screenshots, apply), against about 3 inline.

0. **Prefetch and inspect.** Delegates have no network: fetch every input first. The exception is `--web-search` on a Codex run, which turns on Codex's live `web_search` tool (server-side; the shell stays offline) for research that needs the web. Prefetch `gh` results for such a run anyway. Start long network jobs first in the background; develop against the previous output meanwhile. Inspect the real data before writing rules into a brief. Test a hypothesis with one cheap live sample before writing it into a plan.
   - **Acceptance scripts:** in a `--link`ed folder, do not `resolve()` `__file__`: it follows the symlink into the main checkout, and the script fails before checking anything (2026-10-13, round 1's verify signal lost). Before launch, run every branch of the checker once, e.g. baseline against baseline; a smoke test on the old code usually reaches only the failure path. When a check compares two runs, pin seeds or mask volatile fields such as random IDs. Write the work dir and printed paths relative to the checkout root, and call `sys.executable`: a script written for the main tree first broke in the worktree (2026-10-14). Plant one failure to prove the checker exits non-zero: a tutorial `check.py` printed "N failure(s)" and exited 0, so a verify built on it could never fail. A missing element is a FAIL line, never a traceback (`find`, not `index`), and the self-test includes near misses that must not fire. If the output it checks doesn't exist yet, give the checker a `--self` mode that feeds in its own computation, so both branches run before launch (2026-10-30: a `df.isin` column clash surfaced only in the delegate's run). A fake-package positive control copies the whole package and overrides one module. Capture exit codes before any pipe (`cmd > log; echo $?`). A speed patch's checker records phase timings beside its output. A run's briefs are `brief.md` (latest round) plus `round-*/brief.md`.
   - **Visual checks:** delegates cannot be relied on to run a browser (Codex's headless Firefox crashed in its sandbox, 2026-10-11). Make the screenshots once here with a script (theme and view pinned, each width) and give the folder to every visual reviewer. State known capture artefacts in the brief, such as window-sized captures and blank bands from `min-height: 100vh`.
   - **Decisions:** put 3–4 measured numbers per option into `AskUserQuestion` (e.g. F1 and coverage per policy). Field result: one reply settled four design questions. If a cheap sample settles the question, report the comparison instead of asking. For lasting decisions (design, data policy, public text), run `delegate ask - --agent both < q.md` in the background first, with a self-contained question and a fixed `Pick:` / `Why:` / `Risk others may miss:` reply format; `both` then prints a normalised `## picks` block even when an agent wraps `Pick:` in markdown. Then put each model's pick and its unique risks into the option descriptions. On first use (2026-10-13) the picks agreed, the risks did not overlap, and one model corrected a fact in the question. Neither `ask` agent checks fresh web facts: Cursor's ask mode rejects WebFetch and WebSearch (it does run shell commands such as `ls`, 2026-10-27), and Codex's web tool reads only a cache (its shell has no network). Mark the web facts you checked yourself; live search needs `launch codex --web-search`. A background `ask` re-invokes the session when it ends; don't read its output file or load Monitor meanwhile. For uncommitted work in the main tree, run `delegate review --working-tree --brief F`: it snapshots the dirty checkout into a detached worktree and runs both vendors' review there. It replaces the hand-written `ask - --agent both --effort high` with a patch file (2026-10-20: 3 real defects).
   - **Pilots:** agree the stop rule before the pilot runs ("re-pilot, then decide from the yield"). A 0-of-49 pilot then ended a 4.9M-token search without another question. When a new query or source changes what the input attracts, check that the verifier's candidate rule still separates targets from the new noise: a licence query pulled in CC-licensed mirrors and papers, and candidates rose from 3 to 35.
1. **Quota and pick.** `delegate route <task>` (includes quota). One line to the user: which delegate and why. Before dispatch, Codex `launch`/`followup`/`review NAME`, `review --working-tree` and `ask --agent both` share a check of codex-5h and codex-7d against catalog `min_quota_pct` (10% left by default). It reads `openusage` with source `auto` (15 s timeout); a pool's provider snapshot over 15 min old or missing its timestamp triggers one `direct` refresh (30 s timeout). Failed reads or still-stale pools are unknown and keep the requested agent; run commands print one stderr notice without saving it as a warning. Low explicit Codex dispatches proceed with a persistent warning including the local reset time; default Codex reviews may swap to the frontier fallback, as `ask --agent both` and default working-tree reviews do. Healthy checks are silent. Cursor dispatches, single-agent asks, `--dry-run` and `--preflight` skip this check; detached quota snapshots at job start/end are unchanged. openusage can lag ~1h (`DATA AGE`); use `--source direct` near a limit when inspecting quota manually. Batch independent checks in one Bash call, or parallel tool calls in one message.
2. **Brief.** Pick a template from `templates/` by job type (`implement`, `mechanical`, `review`, `research`). Stable repo conventions belong in the target repo's `AGENTS.md` (verified 2026-10-10: headless Codex reads only `AGENTS.md`; `cursor-agent` reads `AGENTS.md`, `CLAUDE.md` and `.cursor/rules` with `alwaysApply`). Briefs cite it and carry only the deltas. State **intent, not mechanism** — field lesson: "derive must not add columns" made Codex skip new columns; the intent was "prove derive reproduces r012". Cover owned / off-limits files; put a real-data dry run with expected outcomes in `--verify`. Give the reason behind each constraint (Codex follows them literally). When you prescribe a mechanism, also state the invariant it serves and one adversarial case it must survive; two prescribed fixes handled the reported example and failed the case next to it (2026-10-11). Pick the case by kind: a late wakeup for limiters, locks and timers (slots reserved ahead broke spacing under oversleep, 2026-10-27); for a parser or scanner, the invariant plus a case table (continuations, escapes in each quote kind, operators containing `|` or `&`); for a guard, filter or allowlist, one benign event per allowed kind, probed through the real agent first (a fail-closed rule written from adversarial probes alone blocked normal use). Each bound in a spec (≤ N lines, under X s) gets its worst-case test. Check each brief fact against the spec document it paraphrases, not only the data, and name the call that produced it: a paraphrase became the delegate's public wording, and a delegate "confirmed" a wrong fact by re-deriving it the same way. When a delegate reports a brief-vs-docs conflict, re-probe it before review. Make house-style rules countable ("at least N prediction prompts"), and say whether a part that changes inputs other code reads can be committed alone. Compute expected dry-run numbers yourself by a different code path, and ask for any difference with its cause rather than a tuned rule; Cursor then matched them exactly in both rounds. One job per run. Files the brief names outside the worktree, such as another session's scratchpad, may be unreadable in the delegate's sandbox: Cursor's couldn't read 72 screenshots under `/tmp`, so its visual claims were guesses (2026-10-13). Stage them in a gitignored folder of the repo and `--link` it (not yet tested under Cursor's sandbox). For an audit, ask for a reproducible check (command, URL or measurement) with each finding, so verifying means running checks rather than deriving each one again, and ask whether each gate can pass at all once fixed: a missing positive fixture that hides an unsatisfiable gate is P1. When the brief deliberately narrows the spec document, edit the spec before launch. On 2026-10-12, Codex followed the brief, only the reviewer flagged the contradiction, and the guide was fixed after the build. GPT models like tagged sections (`<task>`, `<verification_loop>`, `<default_follow_through_policy>`). The launcher appends the contract (no commits, stay in worktree, flag conflicts, fixed final-message format); do not repeat it.
3. **Launch** with Bash and `run_in_background: true`. **Do not poll.** When the run ends, the exit packet (≤20 lines: state, verify, top files, Digest risks, usage, artifact paths; each risks line comes from the Digest block alone, which ends at a blank line or heading, and is cut at 240 characters; `digest: missing in last-message.md` when the delegate wrote none) arrives in the task notification — that *is* the status. While it runs, write the independent checker for step 5 (another code path, one planted failure that proves it exits non-zero, no code shared with the patch). In the field it was ready when the notification came, and its planted failure gave 17 FAILs and exit 1. Use `--include-uncommitted` when the brief depends on uncommitted edits already in the main tree (otherwise the delegate starts from HEAD, a stderr note names the flag, and the contract and later `review NAME` prompts list up to 20 dirty main-tree paths, `--link`ed ones left out, so neither reports HEAD's copies as wrong).
   ```
   delegate launch codex  --brief B.md --name feat-x --link data/cache --verify 'pytest -q'   # gpt-6.1-sol @xhigh
   delegate launch cursor --brief B.md --name feat-y --verify 'pytest -q'                     # model auto
   delegate launch codex  --brief B.md --read-only --name research-z                          # review/research
   delegate launch codex  --brief B.md --read-only --web-search --name survey-w               # research with live web search
   delegate launch codex  --brief B.md --include-uncommitted --name from-dirty                # base = snapshot of dirty main
   ```
   - `--verify CMD` runs after exit in the cleaned worktree env → `verify.log` / `verify_code`. Pass the real test command, not one piped through `tail` (masks exit code; launch warns). Copy it from the project's CI workflow (`.github/workflows/*.yml`). On 2026-10-12, a bare `pytest -q` collected a release-only test folder: the run reported verify FAIL, and both medium review findings were about the command, not the code.
   - `--preflight` (needs `--verify`): add it to the launch command first when the checker is new or reads `--link`ed inputs. It creates the worktree and links, runs the check once at the base in the same scrubbed environment, prints the tail, exit code and time, then removes the worktree, branch and run folder. No agent starts and nothing is logged. A check of the new work should fail at base on its assertions, not on a path, import or missing input. On this repo (2026-10-13) the base suite took 32 s and a missing checker failed in under a second.
   - **Warnings** never change an exit code. `launch` (with `--dry-run` and `--preflight` too), `followup --brief` and `review --working-tree --brief` print them to stderr before the worktree exists, store them per round in `warnings`, and the packet and `status` repeat them:
     - a `--verify` pipeline whose last stage is `tail`, `head`, `tee`, `cat`, `sort`, `uniq`, `cut`, `tr`, `sed`, `wc` or `column`, when `pipefail` appears nowhere in the command (an asserting `| grep -q` stays quiet);
     - a brief path in a Claude scratchpad (`/tmp/claude-*/`), or in the main checkout and not independently gitignored there: write it repo-relative, or `--link` it.
     - When verify exits 0 but its log has a failure line (`FAILED`, `Traceback`, `N failed`, `not ok`, `AssertionError`, …), the packet, `status` and `--preflight` (full output, not the tail) name the first one. On 2026-10-28 that caught 1 of 114 passing logs: `FAILED (failures=1)` behind `| tail -5`.
   - `--link PATH` symlinks a path from the main checkout and excludes it in `.git/info/exclude` (shared with the main checkout, so launch warns when the path is not independently gitignored there). Cleanup removes the exclude lines this run owns, or transfers them to another live run that still links the path. The path can't be under `.delegate/`, which the worktree uses itself; stage input data in another gitignored folder.
   - **Duration:** Codex @xhigh built a well-specified 1.6k-line module with 48 tests in 16 min (2026-10-12), against a "30–90 minutes" estimate. `delegate ask` on Cursor took from 10 s to 279 s.
   - Parallel runs need disjoint files. `--dry-run` prints `run.sh` and the prompt without creating anything, and refuses the `--link`s the real launch would refuse.
   - For a run not launched in this session (before `/clear`, or `--detach`), run `delegate wait NAME` with `run_in_background`, never a hand-written `sleep` or `until` loop: one exited at `verifying`, before verify ended. `status NAME` gives a snapshot; `--full` only when the packet flags something.
4. **Cross-review** (non-trivial changes): `delegate review NAME` in the background. Other vendor by default (`--agent` / `--focus` override). Reviewer gets the brief plus the diff at `wt/.delegate/review-N.patch`; any single-file diff over 200 KB is replaced there by its header and a note (`--patch-max-kb`; `changes.patch` stays complete). Returns Verdict, findings, spec compliance. `status` warns if a reviewer changed the worktree. The reviewer is asked to challenge the brief too, but a compliance review still tends to approve a wrong brief: twice on 2026-10-10 (a physically wrong acceptance criterion, a broken repo convention). Check domain criteria yourself or ask the user before launch. Put known issues into `--focus` as "already handled: …, ignore"; listed as things to check, they come back as findings (2 of 4 on 2026-10-13). A Codex xhigh review costs ~15 points of codex-5h: start it after your own first pass with those findings listed that way (run blind, 4 of its 4 findings repeated the own list, 2026-10-28). For heuristic code (parsers, scanners, warnings), give real-data frequencies and a stopping rule ("forms that never occur in real input are low"): two reviews of a shell parser each listed 5–6 rarer forms. Reviewers can't run notebooks; for prose that interprets outputs, put a text dump of the executed outputs under `wt/.delegate/` and name it in `--focus`. A small follow-up round that your own read and a real-data check cover needs no second review.
5. **Your own review. Never trust a summary.** Risk-based:
   - **Data / semantic modules** (parsers, validation, matching, accounting, safety guards): read the core files whole; for the tests, a `grep -n "^def test"` outline plus 2–3 tests read in full (~25k tokens for one module).
   - **Rendered output** (notation, plots, UI): look at one real render before accepting an APPROVE, and give the reviewer the PNG: 1,084 passing tests and an APPROVE missed reversed labels.
   - **UI, docs, plumbing:** review the packet's file list and Digest risks, then read only the flagged spots.
   - Send large documents to `delegate ask` instead of reading them here.
   - Re-run tests and the dry run yourself against real data. Adjudicate each reviewer finding; some are wrong.
   - Read the core while the cross-review runs. In the field this found two gaps the review did not list.
6. **Fix rounds.** Brief with accepted findings (or `--from-review N`), then `delegate followup NAME --brief fixes.md`. Archives to `round-<k>/`, resumes the same session and `--verify`. After ~3 rounds without convergence: `--fresh --model <stronger>`. When the last review leaves only 1–10 line fixes, make them inline with tests; another round plus a re-review cost about 0.6M Codex tokens for the same result. A fix brief states the invariant the fix restores and asks for a test of the neighbouring case; for a tokenizer or parser rule, list the adjacent syntax classes (shell: redirects with `&`, continuations, quoting) with one test each (a lone-`&` rule broke `2>&1`, 2026-10-28). Pass your hand-probe script to `followup --verify` beside the gate. Before a round on findings against a warning-only heuristic, count real inputs with that form: zero hits make it a documented limit.
7. **Merge.** `delegate apply NAME --check`, then `delegate apply NAME` (uncommitted on the main tree). Commit only when the user asks, small local commits on a feature branch included. A merge listed in a handoff is not approval: check CI, ask in one line, keep working. In auto mode, collect the destructive or outward git steps (`git rm` of tracked data, commit, push, PR, merge, tag) into one explicit approval request at the end of the item; the classifier blocks them one at a time otherwise. `--3way` if the main tree moved (temp index: updates working files, stages nothing). After merging several delegates' work: one real integrated end-to-end pass with the same cache state as production (cold if production is cold), plus a preflight of offline inputs before long network phases.
8. **Clean up.** `delegate cleanup NAME` removes worktree and branch, keeps the run record; refuses while unapplied. `--purge` deletes the record; `--force` discards changes.
9. **Before outward-facing actions** (emails, scheduled crawls, publishing): check every quantitative claim in docs and briefs against the code that executes. Field incident: docs said ≤1 request/s while code paced 0.1 s apart. For data releases, diff old and new output and check every changed headline value against a source: gates passed on two builds that each carried two false-PD flips. Changed cells outside the item's columns mean cache drift, not the change under review.

Delegates' summaries can be wrong when their code is right (Composer misquoted a brief). Judge the patch and your own re-run.

## Long runs and bulk labelling

- **Read-only is not blind.** Codex read-only and Cursor ask mode can still read reference labels in the repo. Run labelling or eval calls from an empty temp dir (`cursor-agent` then needs `--trust`).
- **Gate each chunk on quota** (`delegate quota --json --source direct`): pause at the codex-5h floor, stop at the 7d or Auto floor, and log quota per chunk. Gauges are whole percents, and a 300-label pilot overestimated the per-label cost about 2×.
- **Pools differ a lot for bulk work.** For 6.5k labels (2026-10-10), grok-4.7-low used about 2.7 points of Cursor Auto, while gpt-6.1-sol@low used about 15 points of Codex 7d and drained the 5h pool once.
- **Detached drivers write their own PID file** (`os.getpid()`). `pgrep` after `setsid nohup` found the launcher's PID instead.
- **Triage verdicts that drive fixes:** when a fix changes timing or structure, re-run the checks on neighbouring elements before review; a "false positive" verdict can turn true once the fix next to it lands.

## Agents

- **Codex** (`codex exec --json`): `-s workspace-write` or `read-only`, `-C <worktree>`, `-o last-message.md`, prompt on stdin. Per-round usage from `turn.completed.usage` lands in meta history. Follow-ups: `codex exec resume <session-id>` (id from log; sandbox via `-c sandbox_mode=…`). Models: `gpt-6.1-sol` (proven), `gpt-6-astra` (~5× $/token), `gpt-5.6-terra` (fast, mechanical). Effort `low`…`xhigh`, then `max`.
- **Cursor** (`cursor-agent -p`, `~/.local/bin`): **`--model auto`** stays the default (Auto pool, SpaceX in-house). Named Grok (`cursor-grok`, `grok-4.7-*`) and Composer (`composer-2.5*`) bill Cursor's "Cursor Models" quota, which is the same pool as Auto (`cursor-auto`), not premium. Use named models only if the user asks, or through the frontier fallback for `ask --agent both` and default reviews when Codex quota is low.
  - Runs with `--sandbox enabled --trust --workspace <worktree> --output-format stream-json`. Sandboxed shell auto-runs; writes outside fail with EPERM; no network.
  - **Never add `--force`**: it silently bypasses the sandbox (tested 2026-10-09). `--unsandboxed` (network, installs) needs the user's OK.
  - `--mode ask` (`--read-only` and Cursor reviews) **cannot run shell**; reads only.
  - Follow-ups: `--resume <session_id>` from the stream init event. If `cursor-agent status` says "Not logged in", the user runs `cursor-agent login`.
- **Claude subagents** (Agent tool, `sonnet|haiku`) appear in `route` for comparison; 0.8 penalty (orchestrator's Claude pool).
- **Codex plugin** (`openai/codex-plugin-cc`): `/codex:review` on the *current checkout*. Use `delegate` for anything that writes.

## Gotchas

- The launcher strips Cursor AppImage variables (`LD_LIBRARY_PATH`, `/tmp/.mount_*` PATH entries), `VSCODE_*`, `CURSOR_*`, `CLAUDE_CODE_*` (including the messaging token), and virtualenvs that belong to another repo.
- Python editable installs: inside the worktree, `import pkg` can resolve to the main checkout. Check with `python -c "import pkg; print(pkg.__file__)"` or use `PYTHONPATH=.`.
- A gitignore rule `dir/` does not match a symlink; `--link` writes exact paths (and `/.delegate`) to `.git/info/exclude`. Paths not independently gitignored (including ones only hidden by a tool `/path` exclude line) are warned at launch; newly appended lines are owned in `meta.excluded` and removed or transferred on cleanup. Only real link symlinks are left out of `changes.patch` and the cleanup dirty check.
- **Codex's sandbox blocks Jupyter kernel sockets** (`nbclient` fails with `PermissionError`). Run extracted cells with the venv's `ipython`, or run notebooks in `--verify`, which runs outside the sandbox.
- **`--link`ed paths are read-only inside Codex's sandbox:** the symlink resolves outside the worktree (`Read-only file system`, tested 2026-10-30). Have the delegate write output under the worktree, and leave writes to linked folders to `--verify`.
- **Clean up only what the session created.** Build into the scratchpad (`--outdir`) instead of deleting the repo's `build/` afterwards.
- **Bash runs zsh:** an unquoted `$var` does not split into words. Loop over a file list with `while read`.
- Untracked files count as changes. `run.sh` exports `PYTHONDONTWRITEBYTECODE=1`, so test runs leave no `.pyc`; other build output (`node_modules`, `dist`) needs a `.gitignore` in the target repo, or it lands in the patch.

## Tuning

`scripts/catalog.json`: delegates (agent, model, effort, AA slug, `aa_proxy`, pools, notes), task weights, `prefer`, `min_quota_pct` (default 10), subagent penalty, and `aa_aliases`, which maps a CLI id (`cursor:<id>` or `codex:<model>@<effort>`) to an AA slug where the two spellings don't match by themselves; add only exact model, version and effort matches. Find AA slugs with `delegate ratings --grep 'gpt-6|grok'`. Without `ARTIFICIAL_ANALYSIS_API_KEY`, ratings come from the public leaderboard ("coding" = Terminal-Bench 4.0 + SciCode mean). Cache: `~/.cache/claude-delegate/aa-models.json` (24h).

Personal tuning belongs in `catalog.local.json` (not in the public checkout the skill symlink points at): `${XDG_CONFIG_HOME:-~/.config}/claude-orchestrator/catalog.local.json`, or `DELEGATE_CATALOG_LOCAL` (set empty to disable). It merges over `catalog.json` with JSON Merge Patch (RFC 7396): `null` deletes a key, scalars and arrays replace, objects merge recursively. `delegates` is the exception, a list of `{"id": ...}` objects: matching ids merge fields (base order kept), new ids (must include `agent` and `model`) append, `{"id": X, "remove": true}` drops X. Top-level keys starting with `_` are comments and are ignored. A delegate's `aa` slug carries the effort suffix, so changing `effort` locally means setting the matching `aa` too. `delegate catalog` prints the local path and override paths; `--json` prints the merged catalog on stdout. A broken local file stops the commands that read the catalog (`route`, `ratings`, `catalog`, `quota --unused`, `ask --agent both`, and Codex `launch`, `followup` and `review`) with one line naming the file; single-agent `ask` and Cursor dispatches don't read it. Cost accounting falls back to `catalog.json` with one stderr line.
