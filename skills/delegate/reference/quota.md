# Delegate quota and tuning

Read before step 1, bulk labelling, long runs or catalog tuning; paths such as `templates/` and `scripts/catalog.json` are relative to the skill folder.

1. **Quota and pick.** `delegate route <task>` (includes quota). One line to the user: which delegate and why. `delegate quota --cached` shows the newest saved reading of each pool from the quota log with no live reader; DATA AGE is `observed_at`'s age, or the row `ts` when that is missing. A preferred delegate (`prefer` or `--prefer`) outranks score only when every pool was read healthily and clears `min_quota_pct`. With a pool unread it sorts by score, tagged `(pref, quota ?)`; below `min_quota_pct` it is `(excluded)`, like any delegate. A delegate with no readable pool still ranks at the 0.7 factor. Before dispatch, Codex `launch`/`followup`/`review NAME`, `review --working-tree` and `ask --agent both` share a check of codex-5h and codex-7d against catalog `min_quota_pct` (10% left by default). `check_dispatch` reads only codex-5h and codex-7d, with one `codex app-server` read bounded at 15 s. It never runs `claude -p /usage` or the Cursor reader. A failed read, or a pool with an error, no timestamp or no remaining figure, is unknown and keeps the requested agent; run commands print one stderr notice without saving it as a warning. Low explicit Codex dispatches proceed with a persistent warning including the local reset time; default Codex reviews may swap to the frontier fallback, as `ask --agent both` and default working-tree reviews do. Without a key or usable ratings cache, the fallback keeps Codex; `ask` prints the ratings error, while reviews keep the low-quota warning. Healthy checks are silent. Cursor dispatches, single-agent asks, `--dry-run` and `--preflight` skip this check; detached quota snapshots at job start/end are unchanged. Quota reads (rows say `"source": "hybrid"`) take Codex from `codex app-server`, Claude from `claude -p /usage` (throttled, with backoff after failures) and, when opted in (`{"cursor_usage_reader": true}` in `${XDG_CONFIG_HOME:-~/.config}/claude-orchestrator/catalog.local.json`), Cursor from a scripted pty read of `cursor-agent`'s interactive `/usage` screen (at most once per 30 minutes; never `cursor-agent -p /usage`). Off by default: Cursor terms ban "harvest, scrape, or extract data from the Service" and "Accessing the Service through automated or non-human means, whether through a bot, script, or otherwise". Off, both Cursor pools error `cursor /usage reader is off; to opt in, set "cursor_usage_reader": true in catalog.local.json` and nothing launches; a hybrid row reused within 15 s may still show old Cursor figures. Fresh hybrid reads show 0m `DATA AGE` on Codex and a new Cursor read; a carried Claude or Cursor reading shows its real age. Cursor gauges are whole percents (`whole_percent` on the pool entry) with the reset at 00:00 UTC of the screen date, so `monitor` takes no per-job cost samples from them; `rounds_left` uses the exact samples from before the cutover. `monitor` skips carried entries, and a session delta needs two distinct observations. Batch independent checks in one Bash call, or parallel tool calls in one message.

## Long runs and bulk labelling

- **Read-only is not blind.** Codex read-only and Cursor ask mode can still read reference labels in the repo. Run labelling or eval calls from an empty temp dir (`cursor-agent` then needs `--trust`).
- **Gate each chunk on quota** (`delegate quota --json`): pause at the codex-5h floor, stop at the 7d or Auto floor, and log quota per chunk. Gauges are whole percents, so small pilots can misestimate per-label cost.
- **Pools differ a lot for bulk work.** For 6.5k labels, grok-4.7-low used about 2.7 points of Cursor Auto, while gpt-6.1-sol@low used about 15 points of Codex 7d and drained the 5h pool once.
- **Detached drivers write their own PID file** (`os.getpid()`). `pgrep` after `setsid nohup` can return the launcher's PID.
- **Triage verdicts that drive fixes:** when a fix changes timing or structure, re-run the checks on neighbouring elements before review; a "false positive" verdict can turn true once the fix next to it lands.

## Tuning

`scripts/catalog.json`: delegates (agent, model, effort, AA slug, `aa_proxy`, pools, notes), task weights, `prefer`, `min_quota_pct` (default 10), subagent penalty, and `aa_aliases`, which maps a CLI id (`cursor:<id>` or `codex:<model>@<effort>`) to an AA slug where the two spellings don't match by themselves; add only exact model, version and effort matches. Find AA slugs with `delegate ratings --grep 'gpt-6|grok'`. `aa_proxy: true` still marks a stand-in model's rating as `aa~`; it does not supply a coding score.

Ratings read only `https://artificialanalysis.ai/api/v2/language/models/free`, using `ARTIFICIAL_ANALYSIS_API_KEY`, else the stripped contents of `~/.config/claude-orchestrator/aa-api-key` (`XDG_CONFIG_HOME` respected). The reader does not enforce mode `0600` and never prints or caches the key. A refresh currently takes 4 pages, with an 8-page safety cap; the free API allows 100 requests per fixed 24-hour window starting with the first request. Cache: `~/.cache/claude-delegate/aa-models.json` (`XDG_CACHE_HOME` respected), still 24h. Only schema 3 is accepted; a failed refresh, including HTTP 429 or a missing key, uses a usable schema-3 cache with a dated warning. A fresh cache needs no key.

Without a key or usable cache, `route TASK` fetches no ratings and ranks by quota only (`QUAL = 1.0`, source `unrated (quota only)`); preferences, quota exclusions and the Claude subagent penalty still apply. One stderr line names `ARTIFICIAL_ANALYSIS_API_KEY` and the key file; `ratings` and `route --frontier` stop with that line and exit 1 instead.

The free API's Coding Index is null for every model, so routing skips the `coding` weight and renormalises the remaining weights. Text `route TASK` output with AA rows prints one Coding Index note explaining this. Text `ratings`, `route TASK` with AA rows and `route --frontier` output credit `Source: Artificial Analysis (https://artificialanalysis.ai/).`; `--json` has no attribution line. Speed uses `performance.median_output_tokens_per_second`, else `performance_v3.mean_output_tokens_per_second`, because AA says `performance` returns null from December 10, 2026.

Personal tuning belongs in `catalog.local.json` (not in the public checkout the skill symlink points at): `${XDG_CONFIG_HOME:-~/.config}/claude-orchestrator/catalog.local.json`, or `DELEGATE_CATALOG_LOCAL` (set empty to disable). It merges over `catalog.json` with JSON Merge Patch (RFC 7396): `null` deletes a key, scalars and arrays replace, objects merge recursively. `delegates` is the exception, a list of `{"id": ...}` objects: matching ids merge fields (base order kept), new ids (must include `agent` and `model`) append, `{"id": X, "remove": true}` drops X. Top-level keys starting with `_` are comments and are ignored. A delegate's `aa` slug carries the effort suffix, so changing `effort` locally means setting the matching `aa` too. `delegate catalog` prints the local path and override paths; `--json` prints the merged catalog on stdout. A broken local file stops the commands that read the catalog (`route`, `ratings`, `catalog`, `quota --unused`, `ask --agent both`, and Codex `launch`, `followup` and `review`) with one line naming the file; single-agent `ask` and Cursor dispatches don't read it. Cost accounting falls back to `catalog.json` with one stderr line.
