# Delegate launch

Read before step 3 to launch, preflight or wait for a run; paths such as `templates/` and `scripts/catalog.json` are relative to the skill folder.

3. **Launch** with Bash and `run_in_background: true`. **Do not poll.** When the run ends, the exit packet (≤20 lines: state, verify, top files, Digest risks, usage, artifact paths; each risks line comes from the Digest block alone, which ends at a blank line or heading, and is cut at 240 characters; `digest: missing in last-message.md` when the delegate wrote none) arrives in the task notification — that *is* the status. While it runs, write the independent checker for step 5 (another code path, one planted failure that proves it exits non-zero, no code shared with the patch). Use `--include-uncommitted` when the brief depends on uncommitted edits already in the main tree (otherwise the delegate starts from HEAD, a stderr note names the flag, and the contract and later `review NAME` prompts list up to 20 dirty main-tree paths, `--link`ed ones left out, so neither reports HEAD's copies as wrong).
   ```
   delegate launch codex  --brief B.md --name feat-x --link data/cache --verify 'pytest -q'   # gpt-6.2-sol @xhigh
   delegate launch cursor --brief B.md --name feat-y --verify 'pytest -q'                     # model auto
   delegate launch codex  --brief B.md --read-only --name research-z                          # review/research
   delegate launch codex  --brief B.md --read-only --web-search --name survey-w               # research with live web search
   delegate launch codex  --brief B.md --include-uncommitted --name from-dirty                # base = snapshot of dirty main
   ```
   - `--verify CMD` runs after exit in the cleaned worktree env → `verify.log` / `verify_code`. Pass the real test command, not one piped through `tail` (masks exit code; launch warns). Copy it from the project's CI workflow (`.github/workflows/*.yml`). A bare test command can collect release-only tests outside CI.
   - `--preflight` (needs `--verify`): add it to the launch command first when the checker is new or reads `--link`ed inputs. It creates the worktree and links, runs the check once at the base in the same scrubbed environment, prints the tail, exit code and time, then removes the worktree, branch and run folder. No agent starts and nothing is logged. A check of the new work should fail at base on its assertions, not on a path, import or missing input.
   - **Warnings** never change an exit code. `launch` (with `--dry-run` and `--preflight` too), `followup --brief` and `review --working-tree --brief` print them to stderr before the worktree exists, store them per round in `warnings`, and the packet and `status` repeat them:
     - a `--verify` pipeline whose last stage is `tail`, `head`, `tee`, `cat`, `sort`, `uniq`, `cut`, `tr`, `sed`, `wc` or `column`, when `pipefail` appears nowhere in the command (an asserting `| grep -q` stays quiet);
     - a path named in the brief's text that sits in a Claude scratchpad (`/tmp/claude-*/`), or in the main checkout and not independently gitignored there: write it repo-relative, or `--link` it. The `--brief` file itself can live anywhere, scratchpad included: launch reads it and copies it to the run's `brief.md`.
     - When verify exits 0 but its log has a failure line (`FAILED`, `FAILED (failures=1)` behind `| tail -5`, `Traceback`, `N failed`, `not ok`, `AssertionError`, …), the packet, `status` and `--preflight` (full output, not the tail) name the first one.
   - `--link PATH` symlinks a path from the main checkout and excludes it in `.git/info/exclude` (shared with the main checkout, so launch warns when the path is not independently gitignored there). `launch` and `followup` accept a path that isn't gitignored, with a warning; `review --working-tree` refuses one. This warning goes to stderr only, isn't stored in `warnings`, so the packet and `status` don't repeat it; `--dry-run` prints it as a preview. Cleanup removes the exclude lines this run owns, or transfers them to another live run that still links the path. The path can't be under `.delegate/`, which the worktree uses itself; stage input data in another gitignored folder.
   - **Duration:** Codex @xhigh built a well-specified 887-line module with 48 tests, about 1.6k lines in all, in 16 min. `delegate ask` on Cursor took from 10 s to 279 s.
   - Parallel runs need disjoint files. `--dry-run` prints `run.sh` and the prompt without creating anything, and refuses the `--link`s the real launch would refuse.
   - For a run not launched in this session (before `/clear`, or `--detach`), run `delegate wait NAME` with `run_in_background`, never a hand-written `sleep` or `until` loop, which can exit at `verifying` before verify ends. `status NAME` gives a snapshot; `--full` only when the packet flags something.
