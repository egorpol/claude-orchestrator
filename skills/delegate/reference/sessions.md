# Delegate sessions

Read before planning session boundaries, deciding whether to delegate, or presenting decisions; paths such as `templates/` and `scripts/catalog.json` are relative to the skill folder.

## Sessions

One work item per orchestrator session. An assessment or a plan counts as an item: hand off after it, before implementation starts. After an item is merged or committed, write a handoff (memory files plus a short `HANDOFF.md`: state, open PRs or runs, next step), then suggest a fresh session or `/clear`. At an item boundary above ~120k context, write the handoff and offer `/clear` in one line *before* starting the next item, even after "go on". A finished build that turns into Q&A support is a new item: its handoff covers tool URL, data layout and decided cases. Offer `/clear` as an option in the picker that closes the first answer, where it is harder to overlook. After `/clear`, `/next` (installed by `install.sh`) continues from `HANDOFF.md`. The context-guard hook (`hooks/context-guard.py`, via `./install.sh --hooks`) fires on the prompt from about 120k and again every 60k. `./install.sh --rules` puts these rules into every session, including ones that never load this skill. With `./install.sh --experiment` (opt-in control sessions), `hooks/session-mode.py` injects them instead, except in `vanilla` controls. `delegate cost --session latest` shows the current session's size and cost.

**Waits over an hour:** the prompt cache expires after 1h idle, so the turn that wakes up re-writes the whole context at 2×. Before a multi-hour wait (a long run, a crawl), write the handoff and continue in a fresh session with `delegate wait`. The context guard holds the first typed prompt after 60 min idle at 100k+ context once and suggests `/clear`; it lets task notifications through. `delegate cost --session` lists the rebuilds.

**Delegate unprompted** by default when a part is mechanical and has a clear spec: every build step with a written spec, all test and doc writing, a near-copy of an existing script, or any step expected to write more than ~40 KB. Prefer a delegate pool whose pace is >1 (share left / share of window left); check `delegate quota` at dispatch, and send work to Cursor when Codex 5h is nearly full even if Codex 7d looks spare. Keep pure judgement, data checks and adjudicating reviews here. Not for changes under ~10 lines unless the user asks: delegation overhead exceeds the work.

- **Decisions:** put 3–4 measured numbers per option into `AskUserQuestion` (e.g. F1 and coverage per policy). If a cheap sample settles the question, report the comparison instead of asking. For lasting decisions (design, data policy, public text), run `delegate ask - --agent both < q.md` in the background first, with a self-contained question and a fixed `Pick:` / `Why:` / `Risk others may miss:` reply format; `both` then prints a normalised `## picks` block even when an agent wraps `Pick:` in markdown. Then put each model's pick and its unique risks into the option descriptions. Neither `ask` agent checks fresh web facts: Cursor's ask mode rejects WebFetch and WebSearch (it runs `ls` but rejects `git show`, 2026-11-04), and Codex's web tool reads only a cache (its shell has no network). Mark the web facts you checked yourself; live search needs `launch codex --web-search`. A background `ask` re-invokes the session when it ends; don't read its output file or load Monitor meanwhile. For uncommitted work in the main tree, run `delegate review --working-tree --brief F`: it snapshots the dirty checkout into a detached worktree and runs both vendors' review there. It replaces the hand-written `ask - --agent both --effort high` with a patch file.
