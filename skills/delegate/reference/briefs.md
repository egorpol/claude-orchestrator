# Delegate inputs and briefs

Read before steps 0 and 2 to prepare inputs, acceptance checks and briefs; paths such as `templates/` and `scripts/catalog.json` are relative to the skill folder.

0. **Prefetch and inspect.** Delegates have no network: fetch every input first. The exception is `--web-search` on a Codex run, which turns on Codex's live `web_search` tool (server-side; the shell stays offline) for research that needs the web. Prefetch `gh` results for such a run anyway. Start long network jobs first in the background; develop against the previous output meanwhile. Inspect the real data before writing rules into a brief. Test a hypothesis with one cheap live sample before writing it into a plan.
   - **Acceptance scripts:** **Scale the checker to the job.** For a change of a few dozen lines, the project's own tests plus one targeted assertion in `--verify` are enough; see that assertion fail once. The rules below are for new modules, parsers, guards and data checks. A checker that isn't tracked is not in the worktree, which starts from HEAD: give it `--link`, or call it by absolute path in `--verify`, which runs outside the sandbox. In a `--link`ed folder, do not `resolve()` `__file__`: it follows the symlink into the main checkout, where the script fails before checking anything. Before launch, run every branch of the checker once, e.g. baseline against baseline; a smoke test on the old code usually reaches only the failure path. When a check compares two runs, pin seeds or mask volatile fields such as random IDs. Write the work dir and printed paths relative to the checkout root, and call `sys.executable` so it works in either tree. Plant one failure to prove the checker exits non-zero; printing failures is not enough. A missing element is a FAIL line, never a traceback (`find`, not `index`), and the self-test includes near misses that must not fire. If the output it checks doesn't exist yet, give the checker a `--self` mode that feeds in its own computation, so both branches run before launch. A fake-package positive control copies the whole package and overrides one module. Capture exit codes before any pipe (`cmd > log; echo $?`). A speed patch's checker records phase timings beside its output. A run's briefs are `brief.md` (latest round) plus `round-*/brief.md`.
   - **Visual checks:** delegates cannot be relied on to run a browser (Codex's headless Firefox crashed in its sandbox, 2026-10-11). Make the screenshots once here with a script (theme and view pinned, each width) and give the folder to every visual reviewer. State known capture artefacts in the brief, such as window-sized captures and blank bands from `min-height: 100vh`.
   - **Pilots:** agree the stop rule before the pilot runs ("re-pilot, then decide from the yield"). When a new query or source changes what the input attracts, check that the verifier's candidate rule still separates targets from the new noise.

2. **Brief.** Pick a template from `templates/` by job type (`implement`, `mechanical`, `review`, `research`). Stable repo conventions belong in the target repo's `AGENTS.md` (verified 2026-10-10: headless Codex reads only `AGENTS.md`; `cursor-agent` reads `AGENTS.md`, `CLAUDE.md` and `.cursor/rules` with `alwaysApply`). Briefs cite it and carry only the deltas. State **intent, not mechanism**: "derive must not add columns" made Codex skip new columns, when the intent was "prove derive reproduces r012". Cover owned / off-limits files; put a real-data dry run with expected outcomes in `--verify`. Give the reason behind each constraint (Codex follows them literally). When you prescribe a mechanism, also state the invariant it serves and one adversarial case it must survive, to catch fixes that only handle the reported example. Pick the case by kind: a late wakeup for limiters, locks and timers (oversleep must not break reserved-slot spacing); for a parser or scanner, the invariant plus a case table (continuations, escapes in each quote kind, operators containing `|` or `&`); for a guard, filter or allowlist, one benign event per allowed kind, probed through the real agent first (to avoid blocking normal use). Each bound in a spec (≤ N lines, under X s) gets its worst-case test. Check each brief fact against the spec document it paraphrases, not only the data, and name the call that produced it, so a wrong paraphrase is not repeated as fact. When a delegate reports a brief-vs-docs conflict, re-probe it before review. Make house-style rules countable ("at least N prediction prompts"), and say whether a part that changes inputs other code reads can be committed alone. Compute expected dry-run numbers yourself by a different code path, and ask for any difference with its cause rather than a tuned rule. One job per run. Files named outside the worktree, such as another session's scratchpad, may be unreadable in the delegate's sandbox. Stage them in a gitignored folder of the repo and `--link` it (not yet tested under Cursor's sandbox). For an audit, ask for a reproducible check (command, URL or measurement) with each finding, so verifying means running checks rather than deriving each one again, and ask whether each gate can pass at all once fixed: a missing positive fixture that hides an unsatisfiable gate is P1. When the brief deliberately narrows the spec document, edit the spec before launch. GPT models like tagged sections (`<task>`, `<verification_loop>`, `<default_follow_through_policy>`). The launcher appends the contract (no commits, stay in worktree, flag conflicts, fixed final-message format); do not repeat it.
