# Delegation rules

When to hand work to Codex or Cursor through the `delegate` skill, from the same field reports.

- **Claude's quota is the scarcest pool.** Before doing mechanical work inline, use the `delegate` skill if the work has a clear spec: tests from a written spec, the same update across several docs, a near-copy of an existing script, or a handoff step that applies a report's listed changes to a doc. Cursor Auto usually has spare quota. Keep design, data checks and review here, and changes under ~10 lines unless the user asks to delegate: a six-line CSS fix took about 8 calls through `delegate`, against about 3 inline.
- **Lasting decisions get second opinions.** Before the picker for a decision that lasts (design, data policy, public text, publishing; not git yes/no or `/clear`), ask Codex and Cursor. Write the question so it stands alone: checked facts, lettered options, and a fixed reply format (`Pick:`, `Why:`, `Risk others may miss:`). Run `~/.claude/skills/delegate/scripts/delegate ask - --agent both < q.md` in the background and keep working (the full path saves loading the skill just to find it). Put each model's pick and any risk the others missed into the option descriptions. In uses through 2026-10-20 the two models mostly picked the same option, and most rounds added a risk or corrected a fact in the question. Answers took 20 s to about 5 min, and about 6 min for a review at `--effort high`. Run the cheap measurable checks before asking, or list them in the question as not yet measured: one risk note contradicted a fact measured minutes later. The background run re-invokes the session when it ends; don't read its output file or load Monitor meanwhile. Neither can check fresh web facts in `ask`: Cursor's ask mode has no web tools, and Codex's web tool reads only a cache. Mark the web facts you checked yourself as such in the question.
